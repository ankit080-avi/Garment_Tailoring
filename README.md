# DarziMate — Tailoring Production Manager

A multi-tenant SaaS PWA for garment workshops. Tracks bulk orders → lots → piece-rate work assignments → daily production → piece-rate payments. Designed for low-friction use on cheap Android phones.

> Sister app to [MilkMate](https://github.com/ankit080-avi/MilkMate). Same architecture, different vertical.

## Roles

| Role | Who | Login | What they see |
|---|---|---|---|
| **Software Admin** | Platform owner (you) | Mobile `8858141463` + password | Every workshop, every order, approval queue, full delete access |
| **Owner** | A workshop owner | Mobile + password | Only their own workshop's orders, contractors, workers, payments |
| **Contractor** | A piece-rate contractor | Mobile + password | Lots assigned to them across every owner they work for, their own workers |
| **Worker** | An individual worker (tailor / cutter / finisher) | Mobile + password | Their own assignments, daily piece counts, earnings |

A contractor can be linked to multiple owners (m:m via `admin_contractors` table). Workers belong to exactly one contractor (1:n via `users.parent_user_id`). Owners run their own shop.

## Architecture

```
[Phone APK / PWA]   ──HTTPS──▶   [GitHub Pages CDN]   ──serves──▶   index.html, app.js, styles.css
                                                                        │
                                                                        ▼
                                            [Supabase Postgres + Realtime + Auth]
```

- **APK** is a Capacitor thin shell that loads the GitHub Pages URL in a WebView.
- **GitHub Pages** serves the static PWA files; service worker caches them.
- **Supabase** holds users, shops, orders, lots, assignments, production entries, payments.
- **Auth**: Supabase email-password with the `<mobile>@karkhana.local` pattern. The fake email never sends real mail.
- **RLS** enforces strict per-role isolation: every policy uses `is_software_admin()` for the platform-admin bypass, plus role/shop checks below.
- **Realtime** subscriptions per table: when a row changes, the relevant user's view re-pulls and re-renders within ~1s.
- **localStorage** acts as a write-through cache for fast first paint and offline reads. Writes go to localStorage immediately and debounce-upsert to Supabase (~350ms).

## Daily workflow — making code changes

### 1. Run locally

```bash
python -m http.server 8767 --directory D:\milkmate\Garment_Tailoring
# open http://127.0.0.1:8767/
```

### 2. Edit files

- `app.js` — all logic, views, routing, RLS-aware Store
- `styles.css` — design system + theme variants
- `index.html` — script tags, modal layer

### 3. Bump cache version

In `index.html`, increment `?v=N` on `styles.css`, `supabase-config.js`, and `app.js` so the service worker picks up new code:

```html
<link rel="stylesheet" href="styles.css?v=N+1"/>
<script src="supabase-config.js?v=N+1"></script>
<script src="app.js?v=N+1" defer></script>
```

And in `sw.js`, bump `CACHE` and the `?v=N` strings in `ASSETS`.

### 4. Deploy to production

Just commit and push — `.github/workflows/deploy.yml` deploys to Pages automatically (~20-30 sec):

```bash
cd D:\milkmate\Garment_Tailoring
git add -A
git commit -m "describe what changed"
git push
```

Watch the deploy at https://github.com/ankit080-avi/Garment_Tailoring/actions.

### 5. Rebuild APK (only when capacitor.config or plugins change)

```bash
cd D:\milkmate\Garment_Tailoring\capacitor-app
npx cap sync android
cd android
./gradlew assembleDebug
cp app/build/outputs/apk/debug/app-debug.apk ../../DarziMate.apk
```

For most code changes you don't need to rebuild — the APK is just a WebView pointing at the live Pages URL.

## Supabase setup (one-time, on a fresh project)

### 1. Project creation

Create a new Supabase project. Pick a region close to your users (Asia-Pacific Mumbai for India).

### 2. Disable email confirmation

DarziMate uses fake `@karkhana.local` emails that never deliver, so confirmation must be off:

- Auth → Providers → **Email** → toggle **Confirm email** off
- Keep **Enable Email Provider** ON

### 3. Run the schema

- Open SQL Editor: https://supabase.com/dashboard/project/_/sql/new
- Paste the entire contents of `supabase/schema.sql` and click **Run**
- Should print "Success. No rows returned." with no errors

The schema is idempotent — safe to re-run any time. It drops and recreates RLS policies, so the latest version always wins.

### 4. Copy URL + anon key

- Settings → API
- Copy the **Project URL** and **anon public** key into `supabase-config.js`:

```js
window.DARZIMATE_SUPABASE = {
  URL:    'https://YOUR-REF.supabase.co',
  KEY:    'sb_publishable_xxx',
  SCHEMA: 'public',
  SOFTWARE_ADMIN_MOBILE: '8858141463'
};
```

### 5. Sign up the software admin

- Open the app → Sign up tab → role = Owner
- Enter mobile `8858141463` (must match `SOFTWARE_ADMIN_MOBILE`) and a password
- The signup auto-elevates this user to `software_admin` role

Future admin signups go to `status='pending'` and wait for the software admin to approve.

## Schema overview

```
shops                  one per Owner; the tenant root
users                  software_admin / admin / contractor / worker; status: pending/active/disabled/rejected
admin_contractors      m:m link between Owners and Contractors
designs                catalog of garment designs per workshop
piece_types            operations within a design (Cutting / Stitching / Finishing) with default piece-rates
orders                 bulk orders (e.g. 1000 shirts of Design A)
lots                   batch splits of an order, each assigned to one contractor
worker_assignments     contractor → worker, qty + rate per piece-type per lot
production_entries     daily piece counts (worker submits, contractor/admin can edit)
payments               advance / settlement / bonus / adjustment, with payer + payee
notifications          per-user inbox
holidays               workshop closed days

views:
v_assignment_progress  pieces done vs assigned + earned amount per worker_assignment
v_worker_balance       total earned − total paid per worker
```

RLS policies: every table has `is_software_admin()` bypass + per-role scoping checks. Helper SECURITY DEFINER functions (`current_role_in_shop`, `current_shop_id`, `current_parent_user_id`) avoid recursive policy evaluation.

## Features

### Software Admin
- Cross-workshop dashboard: total workshops, pending applications, contractors, workers, total pieces, total paid out
- **Pending applications** queue with one-tap Approve / Reject
- **Workshops** list — drill into any workshop to see contractors, recent orders, production stats
- **Hard delete workshop** with `DELETE` confirmation prompt — cascades through every order, lot, assignment, production entry and payment
- 7-day cross-workshop reports

### Owner
- Home dashboard — orders, in-progress lots, contractors linked, workers, total paid
- **New bulk order** modal: design × total quantity × deadline
- **Split order into lots** with per-lot quantity, then assign each lot inline to a linked contractor
- **Designs & piece-rates** catalog (Cutting / Stitching / Finishing with editable rates)
- Contractor list scoped to the workshop's roster only
- "+ Add contractor" supports linking by mobile (existing contractor) OR creating + linking new
- 7-day reports scoped to the workshop

### Contractor
- Lots assigned to them (across every Owner they work for)
- **Lot detail** with worker assignments + per-assignment progress
- **Workers** roster with per-worker earnings, paid, balance
- **Worker detail** drill-down: assignments, recent production entries, payment history; "Pay" button records a cash/UPI/bank settlement
- **Bada Seths** tab — list of every owner they work for with lot count + active count per owner

### Worker
- **Big-tap "+ Pieces done today"** button on home — opens daily entry modal pre-filled with active assignment
- Today / This week / Total earnings stat tiles, plus balance to receive
- Production history (last 30 days)
- Payments received history

### Cross-cutting
- **Themes**: Light · indigo (default), Midnight (dark), Forest, Cream — switch in Settings
- **Profile photo**: tap avatar in Settings → file picker → auto-resize 256 px JPEG → stored as base64 in `users.photo` → displays as topbar avatar across all devices
- **Settings sheet** (gear icon top-right): profile, theme, sign out
- **Refresh button** in topbar (`⟳`) to manually re-pull from Supabase
- **Pull-to-refresh** gesture: drag down at the top of any page to re-pull (works in PWA + APK)
- **Pending approval screen** for new owners — auto-routes to dashboard after approval, or to Rejected screen on rejection
- **Realtime sync** — changes propagate to other devices in ~1 second via Supabase Postgres-changes subscription

## Common debugging

| Problem | Fix |
|---|---|
| App shows old version | Hard-refresh (Ctrl+Shift+R) or force-stop the APK and reopen. Bump `?v=N` in index.html and SW VERSION on next deploy. |
| "Email signups are disabled" on signup | Auth → Providers → Email → ensure **Enable Email provider** is ON. |
| "Database error querying schema" on signup or signin | The auth user is in a half-broken state (often from manual SQL inserts). Wipe auth + profile rows for that mobile, re-run the latest schema, sign up via UI. |
| "infinite recursion detected in policy for relation users" | Old version of `users_select` policy without the `current_parent_user_id()` SECURITY DEFINER helper. Re-run the latest `schema.sql` — it drops and recreates the policy. |
| "Profile row missing" on signin | `auth.users` row exists but `public.users` doesn't. Manually insert: `insert into public.users (id, mobile, name, role, status) select id, 'XXX', 'Name', 'admin', 'active' from auth.users where email = 'XXX@karkhana.local';` |
| Software admin doesn't see new pending application | Pull-to-refresh, or tap the topbar `⟳` button. Realtime occasionally lags ~5s on cold channels. |
| Owner stuck on "Waiting for approval" after admin approves | They need to tap "Refresh status". |
| Owner stuck on "Waiting for approval" after admin rejects | Bug fixed in v=12 — make sure their browser has the latest cache. |

## What's NOT done yet (open follow-ups)

1. **Phone OTP auth** — currently mobile + password (custom). Adding Supabase phone auth via Twilio (~₹6/SMS) would let workers reset passwords more easily.
2. **Photos in Supabase Storage** — currently base64 in DB column. Move to Storage bucket once volume justifies it.
3. **Offline write queue** — reads work offline (localStorage cache). Writes currently fail silently if offline.
4. **Push notifications** — when admin assigns a lot or contractor assigns work, the recipient should get a push. Same FCM pattern MilkMate uses, but unwired so far.
5. **Subscription / billing** — no plan-based gating yet. Software admin approves but doesn't track payments per workshop.
6. **PDF reports** — printable production summary, payslip per worker, settlement receipt.
7. **i18n** — Hindi / Marathi translations of the UI strings.
8. **Edit / soft-delete lots, orders, designs** — currently only hard-delete via Software Admin. Owner-level edits would help in real karkhana use.
